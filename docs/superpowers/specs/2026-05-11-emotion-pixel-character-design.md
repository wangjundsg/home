# 情绪像素小人 V1 Design Spec

## 背景

首页和情侣空间主界面已经先定稿。互动中心旧版暂时废弃，后续会围绕功能大改重新讨论。本规格只定义首页内的“情绪像素小人”功能，不改互动中心，不重做首页整体布局。

用户希望小人表达两个人当前的关系气氛：既能表达风平浪静，也能表达小确幸，还能在有矛盾时从“小乌云”进入更准确的真实状态。

## 目标

V1 要实现一个双方同步的共享情侣状态：

- 小人代表“我们当前的关系气氛”，不拆成“我”和“TA”的两个状态。
- 首页保留三类入口：`我们都好`、`我们的小确幸`、`心里有个小乌云`。
- 点击三类入口只切换分类预览，不立即同步保存，防止误触影响双方状态。
- 点击小人后打开底部选择面板。
- 用户在面板中选择具体状态后，才同步保存为双方共享的当前状态。
- V1 只保存当前状态，不保存历史时间线。
- V1 先使用统一像素占位视觉，后续替换真实像素情侣素材。
- V1 优先跑通情绪传递和双方同步；动态小人作为后续阶段设计，不阻塞 V1。

## 非目标

V1 不做以下内容：

- 不做“我当前状态”和“TA 当前状态”的双人独立状态。
- 不做情绪历史记录、趋势图、时间线。
- 不做互动中心联动。
- 不做真实图片上传、裁切或素材管理。
- 不做逐状态帧动画、精灵图动画、复杂点击互动动画。
- 不做状态解锁、成就、积分奖励。
- 不改已经定稿的首页整体结构，只替换情绪修理站内部结构。

## 状态图鉴

状态分为 3 类，共 24 个状态。

### 我们都好

用于表示关系稳定、没有明显冲突。

1. `calm` — 平静待机
2. `thinking` — 思考中
3. `sleeping` — 睡觉睡觉
4. `studying` — 一起学习
5. `movie` — 看电影
6. `travel` — 一起旅行

### 我们的小确幸

用于表示开心、甜蜜、亲密、想念。

7. `holding_hands` — 牵手
8. `hug` — 拥抱
9. `kiss` — 亲亲
10. `cuddle` — 甜蜜依偎
11. `head_pat` — 摸头杀
12. `happy_jump` — 开心跳跃
13. `blush` — 害羞脸红
14. `miss_you` — 想你中

### 心里有个小乌云

用于表示矛盾、低落、需要修复或需要安全感。

15. `angry` — 生气
16. `wronged` — 小委屈
17. `arguing` — 吵架中
18. `cooling_down` — 冷静中
19. `apologizing` — 道歉中
20. `comforting` — 安慰中
21. `need_hug` — 想被抱抱
22. `low_battery` — 难过掉电
23. `jealous` — 吃醋中
24. `insecure` — 不安害怕

## 首页交互

### 默认加载

1. 首页读取共享当前状态。
2. 如果云端没有状态，默认显示 `calm`。
3. 情绪修理站中显示：
   - 三个分类入口。
   - 当前小人占位视觉。
   - 当前状态名。
   - 一句温柔提示文案。

### 分类切换

1. 用户点击 `我们都好`、`我们的小确幸`、`心里有个小乌云`。
2. 页面只切换当前浏览分类。
3. 不立即写入 Supabase。
4. 小人卡可以显示该分类下的推荐/当前可选状态提示，但不能把共享状态改掉。

这条规则用于防误触：只有选择具体状态才会同步给对方。

### 精确状态选择

1. 用户点击小人卡。
2. 页面弹出底部选择面板。
3. 面板默认打开当前分类。
4. 面板中按分类展示状态按钮，每个按钮至少 44px 高。
5. 用户点击具体状态。
6. 本地立即显示新状态。
7. 同步写入 Supabase。
8. 写入成功后关闭面板，并显示轻量成功反馈。

### 同步失败

如果保存失败：

1. 页面保留本地临时显示，不立刻跳回旧状态，避免体验突兀。
2. 显示温柔提示：`这次没有同步成功，稍后再试一次。`
3. 下次重新进入首页时以云端状态为准。

## 数据设计

V1 只需要一条当前状态记录。

推荐字段：

```ts
interface CoupleEmotionStateRecord {
  id: string
  state_id: string
  updated_by: string
  updated_at: string
}
```

说明：

- `state_id` 对应状态图鉴中的 ID。
- `updated_by` 记录最后一次切换的人，使用现有 `identity`。
- `updated_at` 用于显示或调试最近更新时间。
- 不需要保存 `category`，因为分类可以由本地状态配置表推导。
- 不需要保存历史列表。

## 组件设计

建议拆分，避免把所有逻辑塞进 HomePage。

### `src/data/emotion-character-states.ts`

负责维护状态图鉴配置。

每个状态包含：

```ts
interface EmotionCharacterState {
  id: string
  category: 'good' | 'sweet' | 'cloudy'
  label: string
  shortLabel: string
  description: string
  placeholder: string
}
```

`placeholder` 是 V1 的像素占位符，可先用文字/符号/CSS 小人；未来真实素材接入时再替换为 `imageSrc`。

### `src/hooks/useCoupleEmotionState.ts`

负责：

- 读取当前共享状态。
- 默认回退到 `calm`。
- 保存具体状态。
- 暴露 `currentStateId`、`setCurrentStateId`、`saving`、`error`、`reload`。

### `src/components/emotion/EmotionCharacterCard.tsx`

负责首页小人卡展示：

- 当前状态占位视觉。
- 状态名。
- 温柔提示文案。
- 点击后打开底部面板。

### `src/components/emotion/EmotionStateSheet.tsx`

负责底部选择面板：

- 显示三类状态分组。
- 默认定位到当前浏览分类。
- 具体状态按钮满足移动端触控要求。
- 选中状态有清晰高亮。
- 点击遮罩或关闭按钮可退出。

### `src/pages/HomePage.tsx`

只负责整合：

- 保留首页现有整体布局。
- 将现有情绪修理站内部替换为新的三类标签 + 小人卡 + 状态面板入口。
- 不改首页 Hero、纪念日卡、月亮房卡、今日小纸条、底部导航。

### `src/styles/index.css`

增加：

- 情绪小人卡样式。
- 像素占位视觉样式。
- 底部选择面板样式。
- 状态按钮样式。

## 数据流

1. App 渲染首页。
2. HomePage 使用 `useCoupleEmotionState(identity)` 读取共享状态。
3. 本地状态配置表根据 `state_id` 找到当前状态内容。
4. 用户点击分类标签，只更新本地 `selectedCategory`。
5. 用户点击小人卡，打开 `EmotionStateSheet`。
6. 用户选择具体状态。
7. Hook 先更新本地显示，再写入 Supabase。
8. 写入成功后关闭面板。
9. 写入失败时显示提示，等待用户稍后重试。

## 可访问性与移动端约束

- 所有可点击状态按钮高度至少 44px。
- 图标/占位小人不能成为唯一信息来源，必须显示状态文字。
- 底部面板要有明确关闭方式。
- 分类切换和具体状态选择必须有明显不同的视觉反馈，避免用户误以为点击分类已经同步。
- 文案保持温柔，不使用指责性语言。

## 验证点

### 手工验证

1. 首次进入首页，没有云端状态时显示 `平静待机`。
2. 点击 `心里有个小乌云`，只切换分类预览，不保存云端状态。
3. 点击小人卡，底部面板打开。
4. 选择 `小委屈` 后，首页当前状态变成 `小委屈`。
5. 刷新或另一端打开后，也能看到 `小委屈`。
6. 选择 `我们的小确幸` 下的 `拥抱` 后，双方看到当前状态为 `拥抱`。
7. 保存失败时显示 `这次没有同步成功，稍后再试一次。`
8. 首页不出现纵向滚动，底部导航不遮挡内容。

### 工程验证

- `npm exec eslint -- src/pages/HomePage.tsx src/components/emotion src/hooks/useCoupleEmotionState.ts src/data/emotion-character-states.ts`
- `npm run build`

## 后续扩展

等 V1 交互稳定后，可以追加：

- 将 `placeholder` 替换为真实像素情侣图。
- 增加动态小人设计：先从轻动态开始，如呼吸、眨眼、轻微摇摆、爱心/乌云小粒子；再升级到逐状态帧动画或精灵图动画。
- 增加“最近谁更新了状态”的温柔提示。
- 增加双方独立状态模型。
- 增加情绪历史时间线。
- 与未来重做的互动中心联动。
