# 像素温馨情侣小程序视觉重构设计（Phase 1）

- Date: 2026-05-09
- Product: Qinggan Weihu（私密情侣 PWA）
- Scope: 仅视觉重构，不扩展业务功能
- Priority: 情感氛围优先（甜蜜活泼）

## 1. 背景与目标

当前版本功能基本达标，但 UI 未达到“高品质、统一、温馨可爱像素风”的目标，核心问题是页面视觉语言不一致、氛围表达不稳定、局部可读性与触控体验不统一。

本阶段目标：
1. 在不改业务逻辑的前提下，重构三大核心页面视觉：
   - 首页
   - 情侣空间
   - 互动大厅
2. 建立可复用的视觉语言，消除“拼凑感”。
3. 将第一验收标准锁定为“情感氛围”——打开即有“我们的小世界”的甜蜜活泼感。

## 2. 关键决策

1. 路线选择：视觉重构优先，不重写业务内核。
2. 平台策略：先做手机竖屏 PWA，后续再考虑 App 上架适配。
3. 交付节奏：先设计后实现（先高保真定稿，再编码）。
4. 第一阶段页面：首页 + 情侣空间 + 互动大厅。

## 3. 范围与非目标

### 3.1 本阶段范围（In Scope）

- 三页面高保真视觉重构与实现落地。
- 统一组件视觉体系（Hero / Card / Tag / Button / IconBox / PhotoCard）。
- 统一状态反馈（默认/按下/禁用/完成）。
- 修复影响氛围与可读性的 UI 问题：
  - 文案贴边/溢出
  - 主屏滚动混乱
  - 操作区拥挤
  - 视觉层级不清晰

### 3.2 非目标（Out of Scope）

- 不新增功能模块。
- 不改 Supabase 表结构与核心数据流。
- 不改主导航路由机制。
- 不启动 App 原生双端规范适配。

## 4. 设计原则

1. **情感优先**：视觉表达服务“亲密感、活力感、陪伴感”。
2. **统一优先**：所有主页面共享同一设计语法，不各自为政。
3. **可用优先**：44px 触控底线、清晰文案层级、低认知负担。
4. **克制动效**：活泼但不过度，微动效表达反馈而非炫技。
5. **风险可控**：视觉层替换，功能行为保持一致。

## 5. 视觉系统规范（V1）

### 5.1 色彩

- 主色：暖珊瑚（warm 500/600）用于主行动与情绪锚点。
- 辅色：奶油粉 / 蜜桃橙 / 薄荷绿 / 晴空蓝用于模块区分。
- 中性色：沿用 text-primary / text-secondary / text-muted 保证阅读稳定。
- 约束：功能色面积不超过约 20%，避免高饱和堆叠造成廉价感。

### 5.2 字体与排版

- 标题层级：粗黑，负责情绪聚焦。
- 正文：14–16px，行高 1.45–1.6。
- 辅助信息：最小 12px；标签允许 11px 但需保证对比。

### 5.3 卡片与控件

- 卡片统一：圆角 + 1px 柔边 + 轻阴影 + 轻纹理。
- 禁止每页独立定义风格化 shadow/border 体系。
- 按钮分层：主按钮（实底暖色）/ 次按钮（浅底描边）/ 危险按钮（柔和红）。
- 所有可点击区最小高度 44px，图标按钮必须具备清晰语义。

### 5.4 动效

- 微交互时长：150–220ms。
- 优先按压反馈、状态切换、层级过渡。
- 支持 reduced-motion，避免眩晕与信息噪声。

## 6. 页面级设计边界

### 6.1 首页（Home）

目标：作为“情感入口页”，强化甜蜜活泼氛围与关系状态表达。

约束：
- 主屏固定，不做整页任意滚动。
- 顶部主区域突出“当下关系温度”。
- 保留底部留白，为未来小人动画预留区域。
- 文案与图片组件保证安全内边距，不溢出圆角边界。

### 6.2 情侣空间（Space）

目标：形成“私密花园房间地图”的统一入口体验。

约束：
- 入口卡片遵循统一组件语法。
- 模块差异通过辅色和标签表达，不打破整体风格。
- 结构清晰，避免信息拥挤与误触。

### 6.3 互动大厅（Interact）

目标：形成“游戏机厅入口感”，与情侣空间同体系、不同情绪。

约束：
- 保持与情侣空间同布局节奏，减少学习成本。
- 在 icon / 标签 / 卡片语气上提高活泼感，但不偏离主品牌。

## 7. 三方协作分工

### 7.1 Google Stitch

职责：探索视觉方向和版式候选，快速产出“甜蜜活泼像素风”方案。

### 7.2 Figma

职责：最终设计中枢，沉淀高保真定稿与组件规范。

产物要求：
- 三页面主态稿。
- 状态稿：空态/加载/异常/长文本/禁用/完成。
- 关键尺寸与间距标注。
- 组件级命名与复用关系。

### 7.3 Claude Code

职责：按稿落地、组件化复用、移动端约束校验、构建与部署。

边界：
- 不擅自改动已定稿视觉规则。
- 不在无设计依据情况下新增视觉分支。

## 8. 最小风险实施路径

1. 先在 Stitch/Figma 完成三页面定稿（不写实现代码）。
2. 基于定稿建立组件映射表（Design → Code）。
3. 按页面逐个替换视觉壳（每次只动一页）。
4. 每页通过验收门禁后再进入下一页。
5. 三页完成后做统一回归，再进行生产部署。

## 9. 验收标准（Phase 1）

### 9.1 主验收（情感）

- 首屏感受明确传达“甜蜜活泼”的私密情侣氛围。

### 9.2 一致性验收

- 三页面视觉语言统一，无拼凑感。
- 组件状态行为一致（按压、禁用、完成）。

### 9.3 可用性验收

- 触控区 >= 44px。
- 文案不贴边、不溢出、不重叠。
- 主屏固定策略稳定，无异常整页滚动。

### 9.4 稳定性验收

- 功能行为与当前版本一致。
- 构建通过（TypeScript + Vite Build）。

### 9.5 本轮用户反馈优先修复（Home v1）

根据本轮快速红线检查，当前优先项为 1/3/4；第 5 项（状态帧）降级为建议项（非阻塞）：

1. **氛围红线（优先修复）**
   - 要求：首屏 3 秒内明确传达“甜蜜活泼、我们的小世界”。
   - 设计动作：增强 Hero 情绪锚点（标题语气、主视觉情感符号、暖色重心）；弱化与情感无关的视觉噪音。

2. **可读性红线（优先修复）**
   - 要求：无贴边、无溢出、无重叠、长文案可读。
   - 设计动作：统一文案安全边距；限制标题/描述行数；明确长文案截断与换行规则。

3. **触控红线（优先修复）**
   - 要求：所有主操作区 >=44px，且避免误触。
   - 设计动作：统一按钮最小高度与最小间距；高频操作按钮保留明确文本标签，不使用难辨识的小图标替代。

4. **状态帧建议项（非阻塞）**
   - 建议：补齐默认/按下/空态/加载/长文案 5 种状态。
   - 最小要求：至少明确 Default 与 LongText 两种状态，其他状态可在下一轮补齐。

通过门槛：以上前 3 项改为“通过”后，即可进入页面实现阶段；状态帧在后续迭代补齐即可。

## 10. 风险与缓解

1. **风险：视觉稿与实现稿偏差**
   - 缓解：先组件映射，后逐页实现，逐页对比。
2. **风险：局部改动破坏全局统一**
   - 缓解：统一 token 和核心组件，不允许页面内私有风格分叉。
3. **风险：追求“活泼”导致可读性下降**
   - 缓解：坚持文本层级和对比度下限，动效克制。

## 11. 下一阶段前置条件

在进入实现计划前，需满足：
1. 三页面 Figma 高保真完成并冻结版本。
2. 组件映射表完成并得到确认。
3. 验收清单确认（情感、一致性、可用性、稳定性）。
4. 状态帧采用“最小集”策略：至少明确 Default 与 LongText，其余状态可在下一轮补齐。
